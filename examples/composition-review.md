# Worked composition review — illustrative, not a template

This is a written before/after design example, not a rendered or browser-verified artifact. The observations are informed by the supplied tracker screenshots; the proposed outcome has not been implemented. Keep the same information, core tokens and four equally important stations in both versions.

| Area | Weak composition | Proposed improvement and tradeoff |
|---|---|---|
| Identity | Tiny emblem and title in two shallow, visually disconnected bars | A coherent product header with a legible emblem/title and restrained teal shading. Retain compact navigation; avoid turning it into a large promotional hero. |
| Introduction | Eyebrow, page introduction, metadata, section introduction all compete | Clear page title and short purpose statement; consolidate operational metadata. Keep explanations that help decisions. |
| Peer cards | Large identical boxes with tiny imagery and repeated prose | Give the recommended item and headline value deliberate presence. Align recurring information and use one compact status per card where sufficient. Preserve all details through an appropriate accessible presentation. |
| Data emphasis | Lime values are the only visually strong element | Coordinate title scale, artwork, surface contrast and headline metrics. Keep peers equal; do not crown the largest return as the most important category. |
| Table | Compact aligned data already scans reasonably well | Preserve density and numeric alignment. Improve its heading/filter relationships; do not add gradients or illumination through rows. |
| Administration | Broad panel with fields occupying only part of it | Constrain the form panel to readable field widths or deliberately compose meaningful adjacent content. Do not invent a sidebar to fill space. |

A conceptual reading order could be: product identity/navigation → page purpose and quiet freshness context → four station recommendations → supporting details. This does not mandate a two-column grid, equal card heights or a fixed page width. Choose columns from actual content width and preserve station order on phones.

## Transfer across application types

- **Desktop editor:** compact toolbars, resizable work panes and inspectors; richer branding may sit above quiet technical controls. A viewport exists only because the editing task needs it.
- **Browser dashboard:** readable titles and supporting text, equivalent peer summaries, quiet freshness metadata, compact comparison tables; no substitute viewport is necessary.
- **Catalog:** purposeful artwork and consistent item framing, useful filtering and browsing density. Domain icons may be illustrated while utility controls retain a coherent outline family.
- **Small utility/form:** concise identity, clear labels, comfortable field widths and an obvious primary action. Omit dashboards, cards and persistent status bars unless useful.

## Review the actual result

Ask what attracts attention first, whether useful work appears promptly, whether repeated elements align, and whether surrounding space is intentional. Compare identity and depth with the opened reference images. Check readability and image fallbacks. Correct observed weaknesses, then inspect again. Record visual findings separately from keyboard, reflow, data-edge-state and functional checks.

A future paired visual example should render the same content with weak and improved composition at the same viewport and data state, annotate the differences, and include a constrained-width view. No paired visual mockups or runtime validation are included in this document.
