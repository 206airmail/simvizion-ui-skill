# Icons, motion, accessibility

Prefer Lucide icons (rounded outline caps/joins) at 16px and 1.75px stroke. Compact 14px (optical 1.5–1.75px), prominent/status 20px (1.75–2px). Alternatives permitted when consistent in shape, stroke, and weight; don't mix filled and outlined families indiscriminately. Use utility icons to communicate function. Product emblems and domain artwork may be expressive; see `identity-composition.md`. No separate icon background normally; optional 36px contained icon in informational/feature blocks with elevated or teal-muted tint. Status icons maintain semantic colors. Neutral icon normal `#A6B8BC`, hovered `#EDF4F5`; selection teal `#42CDD2`; warning/error/success retain semantic colors on hover. Primary lime button icons dark. Center icons beside single-line labels, align top to first line in multi-line messages. Standard icon-to-text gap 8px, compact buttons/tabs 6px.

Motion: hover/focus colors ~100ms ease-out, accordion short-panel and user-triggered sidebar/drawer changes 150ms ease-out, dialog/toast fade 150ms. Sidebar collapses width 150ms and workspace follows, drawer translates/fades (not layout width). Automatic responsive changes and tab content switching are **instant**. Long panel collapse can be instant. Never animate controls by bouncing, scaling, or shifting on hover. Honor `prefers-reduced-motion` across all effects; meaningful state changes remain legible without animation.

Keyboard: visible 1px teal focus border without glow, native tab order, Enter/Space activation for buttons, Escape to exit context menus/popovers and cancel dialogs as appropriate, focus trap only in true modal. Preserve input text editing shortcuts; accessible names for icon-only controls, tooltips are supplemental rather than sole names. Announce toasts nonintrusively and don't steal focus. State not communicated through color alone. Maintain adequate contrast, disabled differentiation, and readable text in small layouts.

Visible keyboard focus is mandatory even on lime control surfaces. The default 1px teal border-only focus styling is reserved for dark-surface controls. A lime-filled control or checked checkbox also needs a 2px inset dark contrast ring to remain identifiable; see `references/controls.md`.
