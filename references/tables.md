# Tables, data grids, lists

Choose minimal list for simple browsing; stronger elevated header for substantial grids. Main table background `#0D1B1F`, elevated header `#14272B`; 1px `#294147` row dividers, optional vertical dividers for technical/spreadsheet-like data; no unnecessary cell boxes. Header height 32px, text 12px/500, near-white title-case for elevated headers, muted uppercase for minimal. **Column headers stay fixed vertically** while rows scroll; horizontal scrolling moves both together.

Rows: **36px standard**, **28px dense**, variable height only for descriptive content; 12px horizontal cell padding (8 compact). Uniform background by default, optional subtly alternating `#0D1B1F` / `#14272B` for dense multi-column data. Hover `#1B3237`, selected **background-led** `#194047` without mandatory full teal row outline; an optional narrow selection indicator may reinforce selection in dense lists; keep focus separate and prevent geometry shifts. Text and filenames left; numbers/file sizes and typically time values right, tabular figures; compact icon/checkbox center; headers match data alignment. Default widths follow content; flexible name/description columns take remaining space, min widths prevent unusable values. Large grids/file browsers may resize columns with 6px hit area and subtle/teal divider interaction; short lists auto-size.

Long text: single-line default, end ellipsis for labels, middle for paths/filenames when suffix matters, full text on tooltip if truncated, copy original value; descriptions may wrap when row supports it. Numeric values usually deserve enough width instead of truncation. Sorting indicator active arrow always visible in teal, inactive sort indicator only on hover/focus, with space reserved; 14px icons.

Row actions contextual: essential visible where useful, secondary hover/focus or ellipsis menu, 28px bordered icon controls; touch access remains visible. Multi-selection defaults to desktop row interactions (Ctrl/Shift) where applicable; checkboxes are contextual when useful for batch workflows or touch, not mandatory in every table. Selection uses background-led row emphasis; keyboard/accessibility conventions apply. Bulk toolbar replaces compact table toolbar or appears as separate bar on large tables; selected count 13px semibold near-white, contextual teal tint if not already on tinted bulk bar.

Table toolbar attached/elevated for table-specific actions, separate panel when controlling whole workspace. Search and Filter grouped left; utilities right; group dividers as useful; secondary actions in overflow first, then reflow if search/filter widths are insufficient. Title 14px/600 and optional 11–12px muted item count when useful; active filters can show matching/total counts. Table pagination **only if application needs it**: compact previous/next + page indicator default, numbered where valuable; integrated 40px fixed footer for own table, separate panel for workspace-wide. Table empty state contextual and loading spinner/skeleton follow `notifications.md` visual rules.

## Expanded rows and small details (v1.1)

Expandable row details use a chevron and recessed full-width detail area beneath the original row. **Expanded is not selected**: keep the original row's true selection state separate from expanded state. Selection uses the approved background-led row treatment independently of expansion. See `references/extended-components.md`.

**Right-aligned sortable columns:** right-align the entire heading group (label + 14px arrow), preserving the column's numeric right edge. Place the arrow immediately **before** the label within that right-aligned group when this best preserves the right edge of the numeric header; reserve its space whether active or inactive to prevent shifts. Use an existing active arrow always visible, hover/focus cue for other sortable columns.

Table toolbars: 28px controls in compact toolbar by default (32px standard only when the layout allows). Tag cells, numeric value colors and inline code use `references/extended-components.md`.

## Financial data color restraint (approved)

**Financial-data rule (approved, dense-table hierarchy B):** Ordinary positive values remain near-white `--sv-text`; never color every positive number green. A table **may designate one primary favorable metric column** (e.g., Profit/hr on a craft profitability table) for subdued data green `--sv-value-positive: #A7D5A0`. This designation is based on the metric's importance to the view, **not** merely on a positive sign or the active sort state, and can remain consistent when sorting changes. Use medium/semibold weight and the active sort arrow for hierarchy, without tinted whole-column backgrounds or borders. Keep other favorable Profit, Margin, median, and win-rate columns near-white by default. Reserve additional green for sparse, app-defined meaningful positive exceptions, never another blanket green column. Negative actual losses use `--sv-value-negative: #E8A0A0`, caution uses amber when warranted. If a designated metric is neutral/negative, use appropriate neutral/negative coloring, not green. `--sv-lime` remains for actions, enabled states, but not routine success outcomes or table data. Never rely on color alone.


## Wide-table mobile discoverability and sticky-header trade-off

- When horizontal overflow exists on phones, provide a clear, accessible cue: a subtle edge fade or partial next-column reveal plus an initial short “Scroll sideways for more columns” hint (or equivalent visually and for screen readers). Remove the end-edge cue when scrolled fully to the end. Do not cover data with a permanent opaque overlay; honor reduced-motion and touch scrolling.
- Keep key identifiers (#, name) reachable; sticky first column is optional only where it does not consume most of a small viewport. Horizontal scrolling is preferable to clipping entire columns silently.
- Desktop table headers normally stick while rows scroll. A page-level sticky header can conflict with a table-wide horizontal overflow container. In that case preserve reliable horizontal scroll and alignment even if the header is nonsticky. Breakpoint depends on actual layout, **not a universal 1240px rule**. Avoid nested scrolling traps.
- **Destructive row actions** such as Delete/Clear count as secondary actions when repeated in a data table: on pointer devices they may show on hover/focus or in a row overflow menu, but they must remain discoverable via keyboard and be persistently reachable on touch. Apply existing destructive confirmation conventions for consequential actions.
- **Win-rate / reliability semantics:** do not hardcode universal 90%/50% thresholds. Very high reliability may be green only if meaningfully favorable; mediocre values stay neutral, cautionary values may be amber, and red is reserved for genuine failure/unacceptable risk as defined by the application. Include words/labels or other cues beyond color.


## v1.3 data emphasis clarification

The bright-lime featured-headline exception is for prominent, standalone KPI display roles (including one equivalent featured value per equally important peer card). It **does not** authorize bright-lime numeric columns in dense tables. Continue using one intentionally designated primary favorable column in subdued `--sv-value-positive` green as documented above; ordinary data remains near-white. Sorting alone does not alter semantic color.
