# Windows, panels, navigation, toolbars, tabs, status

## Adaptive window shell
Choose single-workspace for small utilities; sidebar/tabs for multi-page applications; multiple resizable panels for editors. Do not force unused regions. Window `#050C0E` with 6px outer spacing, 6px panel gaps, panels `#0D1B1F` / 1px `#294147` / 6px radius / 12px inner padding. Independent scrolling panels keep header fixed, content scrolls; persistent footer fixed when needed.

Resizable boundaries: only when useful; visually 1px subtle divider, 6px+ drag hit area, hover `#41858D`, active `#42C4CB`; contextually reveal a short grip, no grip on fixed boundaries. Constrain minimum size. Panel headers are **integrated by default**; elevated `#14272B` only when a functional toolbar/persistent control region requires differentiation; 32px default, 28/36 optional, title left at 14/500–600, actions right (28px icon-only controls, 4px internal group gap). Collapsible nested groups chevron on left; standalone panels on right; short groups 150ms height transition, large panels instant. Collapsed standalone panels retain full header; nested groups compact down to title. Panel footer integrated for short forms, distinct fixed elevated bar for scrolling panes; Cancel followed by primary on right, utilities left when present; reflow by content width.

## Navigation sidebar
Separate bordered navigation panel in modular utilities, connected elevated sidebar in integrated shells. Expanded width 180px default, 160–240px recommended; collapsed 48px; default item height 32px (28/36 contextual), 8px horizontal inset, 8px icon gap, 4px item gap. Selected item **full outline** `#42C4CB` and bg `#194047` (do not replace with left accent). Primary destinations Lucide outline icons, nested text-only items allowed; real children indented 32px total, unrelated text-only items not indented. Group only meaningful categories: 11px/500 muted uppercase section headings aligned with **outer left edge** of items, 12px intergroup gap, optional divider.

Sidebar collapse toggle **in sidebar header** (top-right expanded, centered icon-only collapsed), 28px control. Manual sidebar width animation 150ms ease-out, responsive change instant. Save the user's collapsed preference across app launches, but temporary responsive overrides don't overwrite it. Header fixed, navigation items scroll, optional fixed footer for Settings/Help. Single footer action can blend; multiple actions use elevated background/divider. Responsive: expanded → icon-only → hidden + temporary navigation menu. Simple menu dropdown, large nested navigation drawer; drawer default width 240px (220–280), backdrop black 30%, 150ms manual slide/fade. Dismiss with backdrop/Escape.

## Main toolbar
Separate rounded panel for modular apps; connected top application bar for unified shell. Height 40px default (36 compact, 44 spacious), horizontal inset 12px, elevated background. Identity left: name 14/600 near-white, optional 16–20px application icon; project/profile context optional, passive muted separator or vertical 1px divider if it is an interactive project selector. Utility actions right. Toolbar actions use 6px gaps; use subtle separators only between genuinely distinct functional groups, not automatically. Routine controls icon-only with tooltips; important primary actions can carry labels. Keep single row, overflow less-essential groups into ellipsis menu when narrow. Truncate titles at end, file names/paths contextually in middle, show tooltip on truncation.

## Status bar
Optional, integrated strip or separate elevated rounded panel as shell dictates. 28px default (24 simple, 32 interactive), 12px horizontal padding, 11–12px text. Operational state left, related details nearby, independent state right. 7px dots for simple ready/connected/disconnected, 14px semantic icons for warning/error. Pair status indicator with text; interactive status uses subtle hover, teal focus; explicit action stays bordered button. Separate independent groups by 1px/14px dividers; collapse optional data and overflow secondary actionable status at narrow widths.

## Tabs
Connected tab groups are the default: active tab uses selected teal background and a defined cyan-teal boundary that visually joins its content region, without recoloring the entire content panel. Underlined styling is not the default. Height 32px default (28 compact, 36 prominent), text 13px, tab radius 4px for outlined. Content-sized left-aligned workspace tabs; equal-width compact settings groups when useful. Horizontal default, vertical for some settings/tool panels (140px width default, 120–180). Fixed settings tabs no close button. Closable document tab X: active always visible; inactive hover/focus; touch always visible; reserve hit area 20px. Unsaved changes: **6px amber dot before label, after icon if present**; standard modal when closing dirty document. Tab content switches **instantly**. Internal tabs 12px from content (6 compact); integrated workspace tab header separated by divider; content on shared parent for basic settings, recessed sub-surface for code/log/preview. Dynamic tab overflow scroll horizontally; fixed small tab groups overflow into menu. Tab-create action beside tabs, secondary utilities right.

## Public websites

A SimVizion website is not automatically a fixed desktop shell. Public pages normally scroll as a whole and use bounded page and form containers; see `references/web-layouts.md`. Use a fixed-header independent-scrolling layout only in app-like dashboards/editors where justified. Persistent in-page banners and segmented view controls follow `references/extended-components.md`.


## Content-card surfaces and purpose-driven composition (v1.3)

A content-rich card MAY use the unified `--sv-surface-content-raised` (`#101F23`) surface with a standard structural border and contextual 16px padding. Avoid mandatory elevated header/footer strips; split its surface internally only when the sections represent meaningful distinct information groups. Equal peer cards use equivalent hierarchy and styling. Do not confuse a raised content card with the `--sv-selected-bg` selected-navigation surface.

Major screens SHOULD use available area proportionately: dense editors prioritize the workspace, dashboards may use responsive card grids, and simple utilities may remain appropriately narrow. Do not arbitrarily promote one peer based on numerical magnitude. Inspect the entire composition at supported window sizes, not only individual token compliance.

## Identity and shell scope

The dimensions above are starting points for the described desktop patterns. A compact 40px toolbar with a small icon is appropriate for a working toolbar; it is not the universal SimVizion masthead. A product header may use a larger emblem and title, restrained atmospheric shading and useful context. Choose one coherent identity/navigation arrangement rather than stacking redundant bars. Keep primary work accessible below it. See `identity-composition.md` for canonical composition and branding rules.
